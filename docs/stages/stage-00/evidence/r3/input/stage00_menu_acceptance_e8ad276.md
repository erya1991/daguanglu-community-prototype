## 产品评审：容易理解不清的菜单
### V01 基础概况来源
- 功能价值：有，保存人口户数等来自社区/街道的独立统计来源。
- 易混淆点：使用频次可能低，用户容易误以为是统计大屏。
- 建议：建议优先并入“社区房屋档案→社区详情→人口与户数来源”；确认后再动菜单。
- 待决定：是否需要跨多个社区批量维护历史统计口径？

### V02 居民档案 / 房屋绑定 / 正式人房关系
- 功能价值：三者业务不同：人、申请流程、已生效关系。
- 易混淆点：用户会误认为同一件事拆成三个菜单。
- 建议：建议保留数据对象；优先评审把“正式人房关系”并入“房屋绑定→已生效关系”或居民/房屋详情页签。
- 待决定：是否有独立批量管理人房关系的工作场景？

### V03 房屋缺失反馈
- 功能价值：用于住户找不到地址时请求维护方核查和补档。
- 易混淆点：通常是低频异常，独立菜单显眼但价值不直观。
- 建议：建议归入“房屋绑定→地址缺失反馈”页签，保留原数据和处理入口。
- 待决定：是否有独立的多人员补档工单流程？

### V04 设施点位
- 功能价值：跨空间设施检索、分类统计和详情维护。
- 易混淆点：与“社区房屋档案→设施点位”高度重叠。
- 建议：若无跨小区全量筛选/批量管理需求，建议仅保留空间档案内的设施Tab；否则做明确的“全量设施查询”入口。
- 待决定：日常使用者更常按位置找设施，还是按设备编号跨区查找？

### V05 组织资料 / 社区房屋档案
- 功能价值：组织是单位、人员与授权关系；社区是地理空间档案。
- 易混淆点：名称都有“社区/物业”，容易混为同一张主数据。
- 建议：两个对象应保留，菜单与说明明确区分；组织放“组织与权限”组。
- 待决定：组织与小区物业管理单位是否有经确认的统一维护来源？

### V06 账号与授权 / 角色权限
- 功能价值：前者给具体账号分配角色与可见范围；后者定义角色能做什么。
- 易混淆点：仅三个演示角色时看起来配置过重。
- 建议：保留基本权限验证；界面可合并为“组织与权限”模块中的两个页签，避免过多导航。
- 待决定：原型是否需要向研发演示角色配置流程，还是只需表现权限结果？

### V07 结果消息
- 功能价值：模拟审核结果、阅读和业务跳转。
- 易混淆点：信息闭环有价值，但不一定需要独立后台菜单。
- 建议：可评估合并到工作台通知/个人中心；暂保留便于Stage00测试，Stage05统一消息时再决定。
- 待决定：是否有管理员管理消息发送/失败重试的真实业务需求？

### V08 演示身份
- 功能价值：仅为测试角色切换、Mock复位、故障注入。
- 易混淆点：容易被误认为正式产品账号管理。
- 建议：保留为明显标示的演示工具，不纳入正式业务导航与研发生产范围。
- 待决定：研发交付时是否可整体移除演示工具？

### V09 车位资源
- 功能价值：停车业务前置基础档案，记录实体位置和编号。
- 易混淆点：容易误认已支持车位租售、月卡或停车收费。
- 建议：保留在空间档案Tab，明确与Stage01停车交易系统分工。
- 待决定：车位最终权威来源是物业台账还是车场系统？
