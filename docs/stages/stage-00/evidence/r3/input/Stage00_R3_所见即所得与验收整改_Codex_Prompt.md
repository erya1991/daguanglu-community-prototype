## 2. 全局产品原则：模拟数据，不做“演示系统”

### 2.1 四端最终呈现

Web及住户、商户、管理端均按最终产品的布局、名称、表单、列表、详情、操作反馈呈现。

普通界面不得出现：
- “演示模式”“虚构数据”“仅供原型验证”等全局标签；
- “本轮范围”“Stage00/Stage01/Stage02”“后续阶段实现”“由原商城项目交付”等研发交付说明；
- “Mock”“模拟成功”“未接真实接口”“非正式政策”等技术解释；
- “演示辅助”“演示控制”“样例切换”“模拟失败”“回放回执”“复位当前会话”等工具入口；
- session、seed、generation、测试账号ID、接口模式等技术信息。

说明原型边界、数据来源约定、测试限制和生产待接内容，写入README、RESULT或研发交接说明，不放进业务页面。

这不意味着删除真实业务说明：指标口径、单位、文件格式与大小、必要联动、删除二次确认、错误原因仍然保留，而且应使用用户能理解的业务语言。

### 2.2 正常角色切换

保留平台管理员、物业管理员、住户三个既有角色类型；商户端维持原固定商户上下文与独立应用。

Web可以在账号区域用“当前身份／切换身份”切换平台、物业视角，样式像正常账号菜单。不得继续提供“演示身份与辅助工具”大弹窗。各端必要的账号切换不带测试工具、故障开关、数据清理入口。

本轮不制作复杂数据权限、敏感权限或文件授权的展示与配置。管理员在其业务页面默认具备需要的操作能力，无需反复切专项账号或维护可见小区清单才能操作。

角色的业务职责仍有区别：住户看到本人房屋、申请、车辆；物业处理管理业务；商户保持自己的主体上下文。“不展示数据权限”不等于让住户读取所有居民资料，或把所有端合并成全能账号。

已存在的复杂权限逻辑可按兼容需要保留在适配层，但不继续开发成验收重点，不为沿用旧测试而重新加回权限配置界面。不要修改原商城生产权限系统。

### 2.3 数据与辅助能力

- 使用稳定、合理、彼此关联的虚构业务数据；正常展示居民姓名、小区名、车辆、资料，不加“演示”“测试”等前缀。
- 数据在前端正常初始化和保存，列表、详情、统计、跨端关联读取同一份事实，不每次随机改数。
- 复位、种子、故障注入、角色边界专项保留为开发命令或测试夹具，不放到产品入口，也不要通过URL开关重新向普通用户暴露一套辅助界面。
- H5继续使用现有同源数据方案，微信继续本端前端数据，不新增后端。
- 真实接口隔离仍有效；不为“所见即所得”连接真实服务或复制凭据。

### 2.4 所有已出现页面都清理演示包装

包括工作台、首页、我的、服务、商城、商户经营/订单、移动详情和空态。以前验收为PASS的“范围说明页、演示工具”不再按旧预期保留。

## 4. 社区房屋档案（W02-01～W02-12）

根目录 → 小区 → 楼栋 → 单元 → 房间。

无单元楼栋仍为：根目录 → 小区 → 楼栋 → 房间。

- 去掉树节点名称后含义不清的数量数字，保留清晰名称、选中和结构操作。

- 左侧结构维护，右侧始终“房屋空间／设施点位／车位资源”三页签。
- 右侧继续显示所选范围内全部末级资源，不退回直接下级列表。

验收意见同时写了“移除社区树层”和“设施、车位列表展示社区”。两者按显示层区分处理：不恢复独立社区树层、不要求重复选择社区；资源列表的社区字段只读引用已有社区信息或已确认的当前社区上下文。若现有数据不能唯一确定，记录该映射未决，不拿可编辑根名称覆盖所有真实社区归属。

树显示扁平化不等于重建所有数据。已有小区、房屋、申请、关系和Stage01引用保持稳定，内部必要兼容字段可以保留，但不再出现在多余的选择步骤中。

### 4.2 房间与资源列表

房屋空间不再用“所属位置”一列拼接全部地址。至少按独立列展示：
- 小区；
- 楼栋；
- 单元；
- 房间号。

原已存在且有实际意义的面积、用途等字段按当前业务保留。房屋业务编号若没有实际操作必要，从默认列表和新增表单移除；内部稳定标识、CSV匹配键和历史引用不删除，不强制让用户理解内部ID。

设施、车位列表按意见分列展示社区信息、小区、楼栋、单元及对应资源名称/编号。独立设施菜单同样分列。楼栋直属资源的单元留空或显示统一空值，不造默认单元，也不再用一个位置字符串替代所有列。

### 4.3 新建与来源

- 手动创建的资料来源自动默认为“人工维护”，不要求用户反复选择、填写说明。
- 导入时按导入来源带入，不全部改成人工维护。
- 当前已知上级自动带入；不能因少一层社区而错挂小区或楼栋。
- 新增设施和车位只能实际归属楼栋或单元，不再允许直属小区、根目录或房间。
- 选中根或小区时可以作为查询上下文；新增时需选合法楼栋及适用单元，不能直接挂在当前节点。
- 选中楼栋时允许楼栋直属，单元可空；选中单元时准确挂该单元。
- 不增加停车收费、月卡、租售或设备接入。

已有小区直属资源不得静默改挂到某栋楼：保留数据，列出需要重新定位的记录；可编辑纠正归属后保存。若新规则不能直接兼容某记录，给正常的字段校验，不自动丢弃资源或清空会话。

### 4.4 删除替换启停

空间树及房间不再提供“启用／停用”，按负责人要求改为删除并二次确认。独立设施点位菜单也去掉启停，不额外增加报废、退役、资产处置等流程。

删除属于真实改变前端数据的业务动作，不只是从当前列表隐藏一行：
- 确认框包含目标名称与具体位置；取消不产生变化。
- 删除空间结构前检查整个下属范围内是否存在房屋、设施或车位，不只查直接孩子。
- 有这些资源时拒绝删除，清楚提示先处理哪些类型；不能连带删资源。
- 对仍有下级结构节点的对象，采用“先删除下级”的简单安全处理，不增加级联删除功能；这是本轮防误删落地方式。
- 根目录是汇总容器，不提供删除。
- 房间不把自身计为“下属房屋”从而永远无法删除；单独检查它是否被人房关系、申请或已存在的收费/工单等引用。
- 对已有业务引用的房间/资源，保护现有业务，禁止静默删除并留下悬空引用。未批准的级联清理或强删不实现。
- 无引用的空节点/档案删除后，树、列表、选择器和当前统计一致更新；旧记录和历史不得误删。
- 用户取消、校验失败或保存失败时，保持原数据与合理的选中状态。

删除能力具体覆盖到哪些资源，以本轮已明确的空间/房间及现有实现为准，不顺带给全部菜单新增删除按钮。对移除启停后失去业务用途的状态列，同步检查呈现，不能留下不可理解的废字段；不要全仓删除其他阶段仍使用的业务状态。

必须回归有单元、无单元、重复、归属冲突、混合错误、合法文件后换超限文件、重选重试及导入后同步。导入可兼容历史社区编码，但正常模板/界面不再要求多余社区选择；规则变化需更新样表和说明，不能默默读错旧模板。

## 5. 基础概况来源重做为自动统计（W03-01～03）

删除当前“手工录入指标数值”的主要交互，改为：

选择统计空间（树、多选） → 选择指标 → 选择统计日期 → 查询并自动生成结果。

界面要求：
- 统计范围使用本次调整后的空间树，支持多选及已选范围回显；
- 指标可选择人口、户数、设施类别、车位；选择设施类别时使用现有设施分类；
- 日期为正常日期控件；
- 结果通过前端业务数据计算，不由用户填写；
- 结果表显示范围、日期、指标、数值和单位等必要信息，字段简洁；
- 同选父节点和子节点时范围取并集，同一人/户/设施/车位不重复计数；
- 切换范围、指标或日期后，数据重新计算，不能只是改标题或随机变数；
- 删除资源或修改有效关系后，当前统计的相应结果应更新；
- 不额外增加统计大屏、报表配置器、数据仓库或复杂指标平台。

文件未给定人口、户数的精确定义，也未明确日期代表“截至当日”还是“当日新增”。这些不能被Codex伪称为已确认业务规则：
- 优先核对当前已批准规则与现有数据模型；
- 人口不得直接使用登录账号数或人房关系条数；
- 户数不得在没有依据时直接用房间数替代，也不要为凑数新增完整户籍管理模块；
- 设施条目数量与设施实际设备数量不能混用；
- 历史日期须有与日期对应的本地记录、时间信息或预置数据快照，不得用今天的值换一个日期冒充历史统计；
- 可以使用合理的前端本地历史数据，但必须有稳定数据结构和真实计算过程，而不是界面硬编码一组“成功”数字；
- 确实无法从现有资料确定的指标口径记入问题记录，完成其他可计算部分。对应界面使用“暂无该日期数据”等正常业务状态，不填伪0，不用“演示统计／Mock数据”解释，不把未定义的指标标为完全通过。

需要新增的字段仍按六列表规范补齐。菜单改名“基础数据统计”为本提示的落地建议，勿把旧“基础概况来源”名称保留在自动统计页面而造成误解。
