## 2. 验收范围与边界

本次计划验证Web、住户小程序与商户小程序的服务闭环，以及受公共修改影响的管理端框架。覆盖上门、预约到点、商家约时、两次居民确认、状态式取消售后、Web裁定结果、公共资金引用与表32-B经营查询。

所有支付、关闭、退款、分账、回退及凭证均为受控演示行为；不调用真实支付、生产接口、消息或积分服务。H5同源同会话联动与三个微信App本端验证分别记录；工具构建、工具交互、真机均不能互相替代。

默认主线在居民点击付款并通过校验后直接支付成功，在居民确认履约完成且无阻断售后后自动分账成功；不依赖真实商城资金模块或手动查询。必须形成可追溯的独立资金记录和跨端状态，不能只弹出成功提示。刷新与重入不重复付款、分账或累计金额。

Web服务分类、服务审核、服务订单是现有导航下的独立菜单；最终商品／服务页签集成不在本次实现范围。无分账规则配置页、空商品页签或未接入规则页跳转。

支付、分账失败／未知／在途、规则缺失／冲突、回退和资金差异沿原编号保留，前置条件为辅助场景显式注入，不是主线必经步骤。文档确认及默认成功设计不代表场景已通过；实际未执行或受阻如实记录。真机仅在已有获准条件下验证。

不验收容量库存、复杂排班、通知发送、积分发放、物业自营、免费服务、动态报价、取送、任意工作流及线上争议裁定过程；若实现出现这些内容，应作为越界问题处理。
