### 2.5 Stage00 后端接口清单

以下相对路径统一以 `/api/community` 为示意前缀。集合查询支持分页、当前页面已有筛选条件和稳定排序；详情与写入均重新核验主体及数据范围。

| 编号／能力 | 建议接口族 | 主要入参 | 需要返回及落实的规则 |
| --- | --- | --- | --- |
| C01 公共身份及应用上下文 | 复用既有登录；`GET /bootstrap`、`GET /me/scopes` | 应用类型、选中组织或范围 | 当前账号、角色、居民／商户／店铺关联、可见范围、菜单与动作权限；服务端校验上下文选择，不能相信前端自报角色 |
| C02 空间、房屋及车位资源 | `GET /spaces/tree`；`GET/POST /spaces`；`GET/PATCH/DELETE /spaces/{id}`；房屋与车位集合；`POST /house-imports/preview`、`POST /house-imports/{id}/confirm` | 父节点、节点类型、业务字段、版本；导入文件及映射 | 真实层级、完整位置、当前范围各类资源数量、可编辑项；导入行错误及批次结果。房屋数量按房屋记录计，不受分页或设施数量影响；被账单、绑定、停车、工单等引用时禁止删除 |
| C03 居民及个人资料 | `GET/POST /residents`；`GET/PATCH /residents/{id}`；`GET/PATCH /me/profile` | 查询条件、资料及版本 | 居民与账户关系、授权字段、关联房屋摘要；本人仅编辑允许的个人字段 |
| C04 绑定及申请审核 | `GET /bindings`、`GET /binding-applications`；`POST /binding-applications`；`POST /binding-applications/{id}/withdraw`、`/review` | 申请种类、房屋／原关系、申请资料、附件、审核决定、版本 | 申请与有效关系分别返回；审批通过时原子新增／变更／终止关系，驳回不产生有效绑定；条件起止日期合法 |
| C05 房屋缺失反馈 | `GET/POST /missing-house-feedback`；`GET /missing-house-feedback/{id}` | 地点描述、联系信息、可选小区 | 反馈及本人可读列表；Web 有权查询，不自动创建房屋或维修事件 |
| C06 车辆档案与核实 | `GET/POST /vehicles`；`GET/PATCH /vehicles/{id}`；`POST /vehicles/{id}/verify` | 车牌、车辆信息、本人房屋、核实决定及版本 | 规范化车牌、所属住户、核实状态；与停车业务通过车辆 ID 关联，不共用授权状态 |
| C07 设施点位 | `GET/POST /facilities`；`GET/PATCH/DELETE /facilities/{id}` | 类型、空间归属、名称、位置、数量及单位 | 设施记录及真实接入说明；删除按实际引用校验，不用普通启停冒充设备控制 |
| C08 物业人员目录 | `GET /property-personnel`、`GET /property-personnel/{id}` | 组织、姓名、岗位及可选办理资格条件 | 从既有账户体系读取有效人员、岗位、电话；Stage01 派单使用同一目录并追加有效性校验 |
| C09 文件资料 | `GET/POST /documents`；`GET/PATCH /documents/{id}` | 名称、说明、附件 ID、版本 | 文件资料和当前附件；替换保留必要业务引用，不扩展可见版本管理页面 |
| C10 公共附件 | `POST /attachments`；`GET /attachments/{id}/access` | 文件、业务用途、所属对象；读取目的 | 文件 ID、名称、类型、大小、预览／下载地址或流；读取重新验权。公示服务图片与资格证明材料的可见性不同；复用上传设施，不复用成相同权限 |
| C11 基础工作台及计数 | `GET /dashboard/foundation` | 当前可见范围 | 空间、居民、绑定待办等当前数量与跳转筛选条件；与列表口径一致，Stage01／02 指标各由对应业务接口补充 |

### 2.6 必须保持的基础状态与一致性

| 业务对象 | 当前状态／动作 | 结果 |
| --- | --- | --- |
| 绑定申请 | 住户提交 | 待审核；尚未产生新有效关系 |
| 绑定申请 | 待审核 → 本人撤回 | 已撤回；审核不能再使用旧版本完成 |
| 绑定申请 | 待审核 → 有权人员通过／驳回 | 已通过／已驳回；仅通过才按申请类型更新有效关系 |
| 绑定申请 | 已驳回或已撤回 → 重新提交 | 新一轮待审核，保留原关联及历史事实 |
| 车辆 | 登记或重要信息变更 → 核实 | 待核实 → 已确认或已退回；停车关系独立处理 |
| 空间及基础资料 | 更名或修改地址 | 主键与既有引用保留；历史账单、服务订单地址快照不回写 |

### 3.6 关键状态流转

**收费与停车保留三层状态：原业务单据、支付、核销／登记。不能用一个“已完成”字段代替三层事实。**

| 对象／当前环节 | 动作及条件 | 结果 |
| --- | --- | --- |
| 物业账单导入 | 解析、校验、确认有效行 | 形成待发布账单，住户还不能付款 |
| 待发布账单 | 有权人员发布 | 已发布；余额及结清状态独立计算 |
| 可付原单 | 校验归属、版本、余额并创建支付 | 待支付／支付处理中等资金状态；生成唯一原请求 |
| 支付成功 | 后端以可信渠道结果确认 | 写入成功资金事实，再核销账单或登记停车权益；核销／登记失败独立待处理，不再次收款 |
| 支付未知 | 查询原请求 | 未取得确定结果前保留占用，不释放成新的可支付额度 |
| 月租付款完成 | 平台登记成功、厂商未接入 | 显示平台登记与厂商未接入，不能显示真实闸机已生效 |

| 物业工单当前状态 | 角色／动作 | 下一状态与规则 |
| --- | --- | --- |
| 新上报 | 住户或物业提交报修／隐患 | 待派单；保留原上报 |
| 待派单 | 有权物业人员选择本物业有效处理人并派单 | 待处理 |
| 待处理 | 当前处理人开始处理 | 处理中；没有额外接单／拒单状态 |
| 待处理或处理中 | 有权人员说明原因并内部转派 | 待处理；保留原处理材料和责任变更事实 |
| 处理中 | 当前处理人提交结果，有关联住户 | 待确认 |
| 处理中 | 当前处理人提交结果，无关联住户 | 已完成 |
| 待确认 | 原住户确认已解决 | 待评价 |
| 待确认 | 原住户反馈未解决并说明原因 | 待派单，开启新处理轮次，历史结果保留 |
| 待评价 | 原住户评价 | 已完成；物业不能代确认或评价 |

工单类型仅在待派单且从未派单时允许修改；其他资料修正按当前字段规则处理。Stage01 的住户确认仍然保留，不能套用 Stage02 已取消确认的流程。

### 4.6 主线、售后及资金状态

| 当前状态 | 操作者及动作 | 下一状态 | 资金及统计 |
| --- | --- | --- | --- |
| 待付款 | 住户付款，可信结果成功 | 待接单 | 唯一支付成功事实；待接单增加，尚未确认服务安排 |
| 待接单 | 商户接单并派工 | 待服务 | 安排立即生效；不等居民答复，不分账 |

正常新订单不实现改期换人、到场、开始、过程异常、结果补充、补充履约及居民确认完成。历史事实继续可读，不能迁移时伪造这些节点或给旧单补造分账成功。

**演示金额与生产规则分开：**原型 99.00 元按商户 89.00／物业 10.00 演示；59.00 元按商户 53.04／物业 5.96 演示。其他有效新报价使用版本化测试返回。研发需取得真实分配规则、收款关系与渠道能力后接入，不能将演示算法作为正式商业费率；本期没有分账规则配置页面。

### 7.3 公网演示边界

发布一个 HTTPS 站点，四端放在同一域名的四个子路径，保留资源 base。H5 的跨端演示依赖**同一浏览器存储分区、同一源、同一 session**；换电脑、微信内置浏览器或不同访客不会自动共享订单。微信三个 App 当前本地存储也不构成真正跨 App 同步。
